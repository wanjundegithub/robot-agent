# 能力中心收敛改造设计

**日期：** 2026-04-25

## 目标

本次改造只处理已经确认的能力中心收敛需求，不扩展到 Skill 和 MCP 的真实调用，也不调整后端已有的审计与测试记录落库链路。

本次目标有五项：

1. 从能力中心页面和前端接口层移除“测试记录”和“调用审计”功能。
2. 调整能力项表单语义，`Skill` 和 `MCP` 不再展示或要求输入、输出 `Schema`。
3. 为 `API` 类型补充真实 HTTP 请求测试能力。
4. 去掉能力中心页面所有输入框和文本域的 `placeholder` 提示文案。
5. 提供一个可手工录入的“当前服务健康检查”API 配置示例，但不在页面上新增“一键填充示例”按钮。

## 范围

### 纳入本次改造

- 前端页面结构与交互文案调整。
- 前端 API 调用收敛。
- Java 后端 `API` 类型真实测试能力补充。
- 前端能力项表单按能力类型裁剪字段。

### 明确不纳入本次改造

- 不删除后端 `/test-records`、`/audit-records` 接口。
- 不停用后端测试记录和审计记录的落库逻辑。
- 不为 `Skill` 和 `MCP` 增加真实远程调用测试。
- 不新增能力中心中的“填充当前服务示例”按钮。

## 现状问题

### 1. 页面信息过多

当前能力中心详情区包含“测试记录”和“调用审计”两个页签，前端会同步拉取相关数据。对本次目标来说，这两部分会增加页面负担，也不属于本轮需要保留的管理功能。

### 2. 表单语义不一致

当前前端对 `API`、`Skill`、`MCP` 三种能力复用同一套 `inputSchema` / `outputSchema` 字段展示方式，但后端校验逻辑实际上只要求：

- `API`：`url`、`method`
- `Skill`：`skill_name`、`executor_type`
- `MCP`：`server_url`、`protocol`

因此 `Skill` 和 `MCP` 页面继续要求填写 `Schema` 会制造误导。

### 3. “测试”语义不清晰

当前 `testCapability` 更接近“配置校验”，并不会真的向 API 地址发起请求。对于 `API` 类型来说，这不满足用户对“测试接口是否真的可用”的预期。

### 4. 输入提示噪音偏多

能力中心页面存在大量 `placeholder`，虽然能提供示例，但会带来明显的占位噪音。用户已经明确要求全部移除。

## 方案选择

### 方案 A：只做前端删除

- 去掉两个页签和相关请求。
- 保留原有测试逻辑。

优点：风险最低。  
缺点：没有解决 API 测试语义问题，也没有解决 Skill/MCP 的 Schema 误导。

### 方案 B：前后端协同收敛

- 前端删除两个页签和相关请求。
- `Skill` / `MCP` 隐藏 `Schema` 字段。
- `API` 增加真实 HTTP 测试。
- `Skill` / `MCP` 继续保留配置校验。
- 去掉全部 `placeholder`。

优点：改动集中，能同时解决信息裁剪、表单语义和 API 测试语义。  
缺点：需要补充后端真实请求测试实现。

### 方案 C：三种能力都做真实调用

优点：测试语义完全统一。  
缺点：范围明显扩大，需要补 Skill 执行入口和 MCP 客户端测试逻辑，本次不合适。

### 结论

采用方案 B。

## 详细设计

### 一、能力中心页面裁剪

能力中心详情区只保留三个页签：

- 能力项
- 认证与授权
- 发布快照

删除以下页面内容：

- “测试记录”页签
- “调用审计”页签
- 顶部统计卡中的“测试记录数量”

前端同时删除以下内容：

- 获取测试记录的 API 调用
- 获取调用审计的 API 调用
- 相关类型定义
- 相关本地状态
- 相关渲染逻辑

后端现有接口和落库逻辑保持原样，不在本次删除范围内。

### 二、能力项表单字段收敛

#### API

`API` 类型保留以下核心字段：

- 能力编码
- 能力名称
- 能力类型
- 描述
- 认证配置
- URL
- HTTP Method
- Headers
- 输入 Schema
- 输出 Schema

#### Skill

`Skill` 类型保留以下核心字段：

- 能力编码
- 能力名称
- 能力类型
- 描述
- 认证配置
- `skill_name`
- `skill_source`
- `executor_type`
- `endpoint`
- `allowed_capabilities`

`Skill` 类型不再展示：

- 输入 Schema
- 输出 Schema

#### MCP

`MCP` 类型保留以下核心字段：

- 能力编码
- 能力名称
- 能力类型
- 描述
- 认证配置
- `server_url`
- `protocol`
- `tool_name`

`MCP` 类型不再展示：

- 输入 Schema
- 输出 Schema

#### 提交规则

- `API` 继续提交 `inputSchema` 和 `outputSchema`。
- `Skill` / `MCP` 提交时不再要求用户输入 schema。
- 为保持兼容，可以继续向后端传空字符串，也可以在前端构造 payload 时只对 `API` 传 schema；实现时优先选择对现有接口侵入更小的方式。

### 三、API 真实请求测试

#### 测试范围

只对 `API` 类型新增真实 HTTP 请求测试。

`Skill` 和 `MCP` 保持现状：

- 继续执行配置校验
- 不发真实远程请求

#### 后端行为

`testCapability(groupCode, capabilityCode, payload)` 调整为按能力类型分流：

- 如果是 `API`：
  - 先校验 `definitionJson` 至少包含 `url` 和 `method`
  - 按 `definitionJson` 中的 `url`、`method`、`headers` 发起真实 HTTP 请求
  - 记录状态码、响应体、错误信息、耗时
  - 返回真实请求结果
- 如果是 `Skill` 或 `MCP`：
  - 保持原有配置校验逻辑

#### API 测试约束

- 本次只支持无请求体场景，优先覆盖 `GET` 类验证。
- `headers` 从能力定义中读取。
- 如果请求失败，返回清晰错误信息，不吞掉底层异常。
- 保持现有测试记录持久化逻辑兼容。

#### 前端文案

为了避免误解，测试按钮文案按类型区分：

- `API`：真实请求测试
- `Skill` / `MCP`：配置校验

测试结果区域也按类型展示：

- `API` 展示状态码、响应体、错误信息
- `Skill` / `MCP` 展示校验结果

### 四、去掉 placeholder

能力中心页面中所有输入类控件移除 `placeholder`，包括但不限于：

- 能力组弹窗
- 能力项弹窗
- 认证配置弹窗

移除原则：

- 只删除 `placeholder`
- 不删除已有字段标题
- 不删除必要的帮助文案和结果说明

### 五、示例配置说明

本次只提供示例说明，不在页面中新增按钮。

可手工录入的 API 示例：

- 能力编码：`service_health_check`
- 能力名称：`当前服务健康检查`
- 能力类型：`API`
- URL：`http://127.0.0.1:8080/actuator/health`
- HTTP Method：`GET`
- Headers：

```json
{
  "Accept": "application/json"
}
```

- 输入 Schema：

```json
{
  "type": "object",
  "properties": {}
}
```

- 输出 Schema：

```json
{
  "type": "object"
}
```

说明：

- 当前后端默认服务端口是 `8080`。
- 该示例对应现有后端健康检查接口。
- 该示例适合用于验证“能力中心配置”和“API 真实请求测试”链路。

## 影响分析

### 前端影响

- `CapabilityCenterPanel` 需要删减页签、状态、表单字段和文案。
- `services/api.ts` 需要移除两个前端不再使用的能力中心接口方法。
- `types/index.ts` 需要移除或停止引用测试记录、审计记录相关类型。
- 对现有页面布局影响有限，属于局部收敛。

### 后端影响

- `CapabilityService.testCapability` 需要按能力类型分流。
- 需要补充用于真实 API 请求的 HTTP 客户端实现。
- 不调整数据库表结构。
- 不调整审计和测试记录表。

### 风险

- 真实请求测试可能受到目标服务可用性影响，测试结果会比纯校验更不稳定。
- 如果直接展示完整响应体，需要注意长度和错误信息可读性。
- 当前接口测试先只覆盖无请求体路径，后续若要支持 POST/PUT 真正调试，需要额外设计请求体输入能力。

## 测试策略

### 前端

- 回归能力中心页面渲染，确认不再请求测试记录和审计数据。
- 验证页签只剩三项。
- 验证 `Skill` / `MCP` 不显示 `Schema`。
- 验证能力中心页面中不再存在 `placeholder`。

### 后端

- 为 `API` 类型增加真实请求测试用例：
  - 成功请求
  - 目标不可达
  - 配置缺失
- 保留 `Skill` / `MCP` 配置校验测试。

## 验收标准

满足以下条件即可视为完成：

1. 能力中心页面不再出现“测试记录”“调用审计”。
2. 前端不再调用测试记录与审计记录相关接口。
3. `Skill` 和 `MCP` 页面不再展示输入、输出 `Schema`。
4. `API` 类型测试会实际请求目标地址。
5. `Skill` 和 `MCP` 仍然能执行配置校验。
6. 能力中心全部输入框和文本域都不再包含 `placeholder`。
7. 提供的健康检查示例能在本地默认配置下用于验证。
