# 会话历史面板重设计

## 背景

当前前端 `SessionReplayPanel` 同时承担会话列表、执行记录、执行回放详情展示。新的产品目标是把该区域聚焦为“会话历史”：用户只需要看到当前会话和历史会话列表，并能点击任意会话查看该会话的聊天交互记录。

## 已确认需求

1. 不再在该面板展示执行记录、执行回放详情、节点日志或事件流。
2. 会话列表保留当前会话和历史会话。
3. 历史会话可能有零条、一条或多条；当前会话在前台列表中最多一条。
4. 每个会话在列表中只显示一条记录，不显示会话状态，不直接显示会话 ID。
5. 会话标题由前端从该会话首条用户消息截断生成，不需要后端生成或持久化标题。
6. 点击列表中的任意会话后，展示该会话的完整聊天交互记录。
7. 如果会话没有用户消息，前端用“新会话”或时间信息作为兜底标题。

## 推荐设计

### 前端交互

- 将右侧“会话回放”面板调整为“会话历史”。
- 左侧或上方展示会话列表；列表包含当前会话和从后端返回的历史会话。
- 当前会话只出现一次：如果后端列表也返回当前会话，前端按 `session.id` 去重。
- 会话列表项显示：标题、最近活动时间；不显示状态、会话 ID、执行 ID。
- 点击会话列表项后，详情区展示该会话消息流。
- 当前会话详情直接复用内存中的 `messages`，避免重复请求。
- 历史会话详情通过 `GET /api/sessions/{sessionId}/messages` 加载。
- 标题生成规则：取第一条 `type === 'user'` 的消息内容，去除多余空白后截断；若不存在，显示“新会话”。

### 后端接口

- `GET /api/sessions?userId=...` 返回该用户所有会话，而不是仅返回 `ACTIVE` 会话。
- 返回顺序按 `lastActivityAt` 倒序，确保最近会话优先。
- `SessionResponse` 暂不增加标题字段，避免引入后端标题生成和持久化复杂度。
- 保持 `GET /api/sessions/{sessionId}/messages` 作为会话消息详情接口。

### 数据处理

- 前端会先组装一个会话候选列表：当前会话 + 后端会话列表。
- 使用 `session.id` 去重，每个会话只保留一条前台记录。
- 为生成标题，前端需要知道首条用户消息：
  - 当前会话：直接使用当前 `messages`。
  - 历史会话：首次展示时可先显示“新会话”，点击或懒加载消息后更新标题。
  - 如需让列表标题在未点击前也准确，可由前端批量/并发加载历史会话消息，但实现时需要控制请求数量，避免会话很多时过度请求。

## 实现取舍

推荐采用“懒加载标题”的轻量方案：列表先展示最近会话与兜底标题；当用户点击某个历史会话加载消息后，根据首条用户消息更新该项标题。这样不需要后端新增摘要字段，也避免页面初始化时对所有历史会话发起大量消息请求。

如产品强要求列表初始化时每个历史会话都显示首问摘要，可以在第二阶段做受限并发加载，或新增后端轻量摘要接口；本次不做。

## 验收标准

1. 页面不再出现会话回放详情、执行记录列表、节点日志或事件流内容。
2. 当前会话在会话列表中只出现一条。
3. 历史会话可出现零条、一条或多条，每个会话只出现一条。
4. 会话列表项不显示状态和会话 ID。
5. 点击历史会话后能看到该会话的聊天交互记录。
6. 有用户消息的会话在消息加载后使用首条用户消息截断作为标题。
7. `npm run check:text`、`npm run build`、相关 E2E 测试通过。
8. 后端编译测试通过，联调时 `/api/sessions?userId=` 能返回当前和历史会话集合。

## 非目标

- 不在本次实现后端 AI 摘要、标题字段或标题持久化。
- 不在该面板展示 execution replay、节点日志、事件流。
- 不改变主聊天区发送消息和 WebSocket 交互协议。
