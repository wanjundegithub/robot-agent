# Phase 5 Handoff Checklist

## 角色分工

- `tech-leader`: 产出 Phase 5 拆解方案、接口冻结清单、风险清单、最终评审意见
- `backend-java`: 产出 ABAC、二次确认、熔断 / 限流 / 降级入口、审计实现与生产接口优化
- `python-dev`: 产出运行时限流、降级、二次确认、高风险工具保护和向量访问优化挂点
- `frontend`: 产出高风险确认 UI、权限反馈、降级提示和运行状态展示
- `platform-reliability`: 产出索引优化、Redis 集群边界、向量分片策略、日志归档和清理自动化方案
- `security`: 产出 ABAC / 二次确认 / 日志归档清理链路的脱敏要求、暴露边界和残余风险清单
- `qa`: 产出性能、稳定性、权限、安全、清理自动化与回归验证结果

## 先冻结的合同

- ABAC 策略模型、属性来源、表达式约束和拒绝口径
- 高风险操作清单、确认对象、确认时效、审计写点和前端交互合同
- 熔断器、降级策略、限流粒度和触发条件
- 数据库索引优化目标、Redis 集群边界、向量分片边界与数据迁移策略
- 日志冷热分层、归档格式、保留期、清理任务和恢复入口
- 审计、日志、Telemetry、权限与清理中的关键字段和命名

## 并行策略

1. `tech-leader` 冻结目录结构、合同和验收边界
2. `platform-reliability` 先冻结性能、稳定性和归档清理方案
3. `backend-java` 与 `python-dev` 对齐 ABAC、确认流程、熔断、限流和降级事件后并行开发
4. `security` 并行冻结权限、确认、归档和清理中的最小暴露与审计边界
5. `frontend` 根据合同并行开发确认、权限反馈和降级界面
6. `qa` 从合同和 Phase 5 目标反推压测、故障、权限和清理验证
7. `tech-leader` 做最终集成审查与范围回收

## 角色输出格式

- 变更摘要
- 影响的接口、表、事件、策略或存储方案
- 影响的索引、缓存、分片、限流、熔断或归档清理规则
- 未完成项
- 风险或阻塞项
- 对 Phase 5 目标的覆盖说明

## 定义完成

- 数据路径具备性能优化控制点
- 稳定性保护机制可验证
- 日志归档与清理自动化可验证
- 权限细化 (ABAC) 可执行
- 高风险操作二次确认可执行
- 无明显范围漂移，且不回归 Phase 1 / Phase 2 / Phase 3 / Phase 4
