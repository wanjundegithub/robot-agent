## 1. 总体概述

### 1.1 系统定位

服务机器人是一个面向业务服务场景的智能对话系统，支持：
- 基于意图识别的流程路由
- 可编辑可视化流程画布的流程定义
- 大模型、知识库、业务接口的集成调用
- 流程暂停、恢复、失败重试和结果追踪

### 1.2 V1 核心能力

| 能力 | 说明 |
|------|------|
| 意图识别 | 路由到对应工作流 |
| 流程执行 | 按图编排执行节点 |
| 人机交互 | 表单补充信息 |
| 知识问答 | RAG 检索 |
| 流程追踪 | 全链路审计 |

### 1.3 V1 不做的内容

- 任意多代理自由协作
- 无边界的自动跨流程跳转
- 开放式长期记忆写入
- 自动修改工作流定义
- 复杂工作流市场或多租户计费

### 1.4 本轮优化约束

- 主执行链路禁止返回 Mock / Demo / Stub 数据；意图识别、知识检索、工具调用和流程执行必须走真实配置或明确失败。
- 前端与 Java 后端的业务主链统一为 `Netty + WebSocket` 双向通信；HTTP 仅保留后台管理、文件上传和健康检查等非主交互场景。
- 前端编排器必须是可编辑画布，而不是只读拓扑图；至少支持拖拽、连线、删除、节点属性编辑、校验和保存。
- 意图命中、知识库查询改写、知识回答和通用 LLM 节点都必须走可配置的大模型 Profile，不能在代码里写死模型选择。

### 2.3 通信方案决策

**选择**: `Netty + WebSocket`（前端 ↔ Java） + `HTTP + SSE`（Java → Python）

**理由**:
1. 对话消息、表单提交、画布编辑、执行事件推送都属于双向低延迟交互，适合统一收敛到单个 WebSocket 通道。
2. Netty 可以更细粒度控制连接生命周期、心跳、背压、顺序投递和高并发连接数。
3. 画布编辑和执行事件共享同一连接后，前端可以基于统一的 `action / ack / event` 协议处理业务。
4. Java → Python 仍保留 HTTP + SSE，便于保留现有执行引擎的流式输出模型。
5. 主交互链路去 HTTP 化后，可以减少请求风暴和前端轮询复杂度。

**适用场景**:
| 场景 | 协议 |
|------|------|
| 前端 ↔ Java 后端 | Netty + WebSocket |
| Java → Python 执行引擎 | HTTP + SSE (流式输出) |
| 后台管理 / 文件上传 | HTTP |
| 内部服务间通信 | HTTP (REST) |

## 4. 工作流引擎设计

### 4.1 节点类型总览

| 节点类型 | 说明 | 输入 | 输出 | 是否挂起 |
|---------|------|------|------|----------|
| `start` | 流程入口 | 无 | 初始变量 | 否 |
| `end` | 流程出口 | 最终结果 | 格式化输出 | 否 |
| `llm` | 大模型调用 | prompt + 上下文 | 模型响应 | 否 |
| `knowledge` | 知识检索 | 查询词 | 检索结果 | 否 |
| `tool` | 外部工具调用 | 工具参数 | 工具返回 | 否 |
| `condition` | 条件判断 | 条件表达式 | 分支选择 | 否 |
| `form` | 人机交互 | 缺失字段定义 | 用户填写 | **是** |
| `subflow` | 子流程调用 | 子流程参数 | 子流程输出 | 否 |

### 4.2 统一执行契约

所有节点遵循统一执行模式：

```
┌───────────────────────────────────────────────────────┐
│                    节点执行契约                         │
├───────────────────────────────────────────────────────┤
│                                                       │
│  1. Input Mapping  (输入映射)                          │
│     ↓                                                │
│  2. Validation      (参数校验)                         │
│     ↓                                                │
│  3. Execute         (执行逻辑)                         │
│     ↓                                                │
│  4. Error Handling  (错误处理)                         │
│     ↓                                                │
│  5. Output Mapping  (输出映射)                         │
│     ↓                                                │
│  6. Next Decision   (下一跳决策)                       │
│                                                       │
└───────────────────────────────────────────────────────┘
```

### 4.3.1 前端可编辑可视化流程画布

前端编排器不是只读展示，而是工作流定义的主编辑入口。画布能力要求如下：

- 节点操作：支持新增、拖拽、复制、删除、分组、快捷键撤销/重做。
- 连线操作：支持拖拽连线、修改条件分支、删除边、校验悬空节点。
- 属性面板：支持编辑节点名称、Prompt、输入/输出映射、超时、重试、模型 Profile、知识库 Profile、工具权限范围。
- 画布元数据：保存 viewport、节点坐标、分组信息、折叠状态、最后编辑人和最后保存时间。
- 校验能力：前端实时校验入口节点、出口节点、循环依赖、未映射变量、缺失模型配置、缺失知识库配置和高风险工具确认要求。
- 保存策略：支持草稿保存、发布预检查、版本对比和回滚预览。

**关键约束**:

- 画布预览不能通过 Mock 节点结果伪造执行成功；预检查只做结构校验、配置校验和连通性校验。
- 节点调试若需要运行，必须调用真实测试环境配置，并在 UI 中明确标注 `sandbox` / `staging` 环境。

### 4.4 会话状态机

#### 状态定义

| 状态 | 说明 |
|------|------|
| `IDLE` | 空闲，无激活流程 |
| `ROUTING` | 意图识别中 |
| `RUNNING` | 流程执行中 |
| `WAITING_USER` | 等待用户补充信息 |
| `WAITING_TOOL` | 等待外部工具结果 |
| `SUSPENDED` | 流程被暂存 |
| `COMPLETED` | 本次流程完成 |
| `FAILED` | 执行失败 |
| `CANCELLED` | 用户取消 |

#### 状态转换规则

```
IDLE → ROUTING: 收到新消息且无激活流程
  ├─→ RUNNING: 意图匹配到工作流且置信度 > 阈值
  ├─→ IDLE: 意图识别失败，转通用问答
  └─→ WAITING_USER: 需要用户澄清意图

RUNNING → WAITING_USER: 遇到 form 节点且字段缺失
RUNNING → WAITING_TOOL: 调用异步工具
RUNNING → SUSPENDED: 用户确认切换到新流程
RUNNING → COMPLETED: 流程正常结束
RUNNING → FAILED: 达到重试上限或致命错误
RUNNING → CANCELLED: 用户主动取消

WAITING_USER → RUNNING: 用户提交表单且校验通过
WAITING_USER → FAILED: 表单校验失败超过次数
WAITING_USER → CANCELLED: 用户放弃提交

WAITING_TOOL → RUNNING: 工具调用完成
WAITING_TOOL → FAILED: 工具调用失败超过重试次数

SUSPENDED → RUNNING: 用户选择恢复原流程
SUSPENDED → COMPLETED: 用户放弃恢复

FAILED → IDLE: 用户重新发起对话
CANCELLED → IDLE: 用户重新发起对话
```

## 6. 运行时机制

### 6.1 幂等性设计

**三层幂等控制**:

#### 1. 消息级幂等

```python
def handle_message(session_id, message_id, content):
    """处理用户消息，保证幂等"""
    idempotency_key = f"msg:{session_id}:{message_id}"
    cached_result = redis.get(idempotency_key)

    if cached_result:
        logger.info(f"Message {message_id} already processed, returning cached result")
        return json.loads(cached_result)

    # 处理逻辑
    result = process_message(session_id, content)

    # 缓存结果（24小时）
    redis.setex(idempotency_key, 86400, json.dumps(result))
    return result
```

#### 2. 表单提交级幂等

```python
def submit_form(execution_id, submit_id, form_data):
    """提交表单，保证幂等"""
    submit_key = f"form_submit:{execution_id}:{submit_id}"

    if redis.exists(submit_key):
        logger.info(f"Form submit {submit_id} already processed")
        return {
            "status": "already_processed",
            "execution_id": execution_id,
            "result": get_cached_result(execution_id)
        }

    # 处理表单
    result = process_form(execution_id, form_data)
    redis.setex(submit_id, 86400, "1")
    return result
```

#### 3. 工具调用级幂等

```python
# 工具配置中声明是否需要幂等
tool_config = {
    "tool_code": "flight_search_api",
    "idempotent": True,  # 搜索类工具可幂等
    "idempotency_key_pattern": "${tool_code}:${hash(input)}"
}

async def execute_tool_with_idempotency(tool_code, params):
    """执行工具调用，支持幂等"""
    if not tool_config[tool_code]["idempotent"]:
        return await execute_tool(tool_code, params)

    # 生成幂等键
    input_hash = hashlib.md5(json.dumps(params, sort_keys=True).encode()).hexdigest()
    idempotency_key = f"tool:{tool_code}:{input_hash}"

    # 检查缓存
    cached = redis.get(idempotency_key)
    if cached:
        return json.loads(cached)

    # 执行工具
    result = await execute_tool(tool_code, params)

    # 缓存结果（根据工具类型决定缓存时长）
    cache_ttl = tool_config[tool_code].get("cache_ttl", 3600)  # 默认1小时
    redis.setex(idempotency_key, cache_ttl, json.dumps(result))

    return result
```

**ID 生成策略**:

| 场景 | ID 生成方式 | 格式 |
|------|------------|------|
| 消息 | 前端生成 | UUID v4 |
| 表单提交 | 前端生成 | UUID v4 |
| 工具调用 | 后端生成 | ULID |
| Execution | 后端生成 | ULID |

```python
RETRY_POLICIES = {
    "network_timeout": {
        "max_retries": 3,
        "backoff": "exponential",
        "initial_delay": 1000,  # ms
        "max_delay": 10000,
        "retryable_errors": ["timeout", "connection_error", "dns_error"]
    },
    "rate_limit": {
        "max_retries": 2,
        "backoff": "fixed",
        "delay": 5000,
        "retryable_errors": ["rate_limit_exceeded"]
    },
    "llm_service_error": {
        "max_retries": 2,
        "backoff": "exponential",
        "initial_delay": 2000,
        "max_delay": 8000,
        "retryable_errors": ["internal_error", "service_unavailable"]
    },
    "validation_error": {
        "max_retries": 0,
        "on_error": "fail",
        "retryable_errors": []
    },
    "permission_denied": {
        "max_retries": 0,
        "on_error": "fail",
        "retryable_errors": []
    }
}

async def execute_with_retry(node_config, execute_func):
    """带重试的执行"""
    policy = RETRY_POLICIES.get(
        node_config.get("retry_policy", "network_timeout")
    )

    last_error = None
    for attempt in range(policy["max_retries"] + 1):
        try:
            return await execute_func()
        except Exception as e:
            error_type = get_error_type(e)

            if error_type not in policy["retryable_errors"]:
                raise

            if attempt == policy["max_retries"]:
                raise

            last_error = e

            # 计算延迟
            if policy["backoff"] == "exponential":
                delay = min(
                    policy["initial_delay"] * (2 ** attempt),
                    policy["max_delay"]
                )
            else:
                delay = policy["delay"]

            await asyncio.sleep(delay / 1000)
            logger.warning(f"Retry {attempt + 1}/{policy['max_retries']} after {delay}ms")

    raise last_error
```

### 6.3 资源隔离

#### 1. 进程隔离

```python
from concurrent.futures import ProcessPoolExecutor

class WorkflowExecutorPool:
    """工作流执行进程池"""

    def __init__(self, max_workers=4, max_tasks_per_child=100):
        self.executor = ProcessPoolExecutor(
            max_workers=max_workers,
            max_tasks_per_child=max_tasks_per_child
        )

    async def execute(self, workflow_code, execution_id, inputs):
        """在工作流隔离进程中执行"""
        future = self.executor.submit(
            run_isolated_workflow,
            workflow_code,
            execution_id,
            inputs
        )
        return await asyncio.wrap_future(future)
```

#### 2. Token 消耗限制

```python
WORKFLOW_TOKEN_LIMITS = {
    "flight_booking": 10000,
    "hotel_booking": 8000,
    "general_query": 2000,
    "default": 5000
}

class TokenLimiter:
    """Token 消耗限制器"""

    def __init__(self):
        self.workflow_tokens = defaultdict(int)
        self.lock = asyncio.Lock()

    async def check_limit(self, workflow_code, additional_tokens):
        """检查是否超出限制"""
        limit = WORKFLOW_TOKEN_LIMITS.get(
            workflow_code,
            WORKFLOW_TOKEN_LIMITS["default"]
        )

        async with self.lock:
            if self.workflow_tokens[workflow_code] + additional_tokens > limit:
                raise TokenLimitExceededError(
                    workflow_code=workflow_code,
                    consumed=self.workflow_tokens[workflow_code],
                    limit=limit
                )

    async def record_consumption(self, workflow_code, tokens):
        """记录消耗"""
        async with self.lock:
            self.workflow_tokens[workflow_code] += tokens
```

#### 3. 用户级限流

```python
class UserRateLimiter:
    """用户级限流（滑动窗口）"""

    def __init__(self, window=60, max_requests=10):
        self.window = window  # 秒
        self.max_requests = max_requests

    async def check(self, user_id):
        """检查是否超出限流"""
        key = f"rate_limit:{user_id}"
        now = time.time()

        # 移除窗口外的记录
        redis.zremrangebyscore(key, 0, now - self.window)

        # 获取当前窗口内的请求数
        current_count = redis.zcard(key)

        if current_count >= self.max_requests:
            raise RateLimitExceededError(
                user_id=user_id,
                current=current_count,
                limit=self.max_requests
            )

        # 记录本次请求
        redis.zadd(key, {str(uuid4()): now})
        redis.expire(key, self.window + 10)
```

```python
class NodeContext:
    """节点上下文，限制变量大小"""

    MAX_VARIABLES = 100
    MAX_STRING_LENGTH = 10000
    MAX_ARRAY_LENGTH = 1000

    def __init__(self):
        self.variables = {}

    def set_variable(self, name, value):

        # 字符串截断

        # 数组截断

            value = value[:self.MAX_ARRAY_LENGTH]

        self.variables[name] = value
```

### 6.4 去 Mock 化运行约束

为避免测试阶段遗留的假数据逻辑进入生产主链路，运行时必须遵守以下规则：

- 意图识别：只能调用已启用的 `intent_routing` 大模型 Profile，或明确走规则兜底；不能返回硬编码意图。
- 知识检索：只能读取真实知识库版本、真实索引和真实 rerank / answer 配置；不能内置假文档或伪造命中结果。
- 工具调用：只能调用注册工具或显式失败；不能在运行时返回本地拼装的“模拟业务成功结果”。
- 画布调试：默认只做结构校验和配置校验；若执行节点调试，必须连接测试环境 Provider，并记录调试环境。
- 配置缺失：Provider、Secret、Model Profile、Knowledge Base Version 缺失时应快速失败，并在前端给出明确错误。

### 9.1 Prompt 注入防护

```python
import re

class PromptSanitizer:
    """Prompt 清洗器"""

    INJECTION_PATTERNS = [
        r'(ignore|forget|disregard).*(above|previous|instruction)',
        r'(as an? )?(ai|assistant|model|system)',
        r'(output|print|display).*(system|prompt|instruction)',
        r'<\|.*?\|>',
        r'```.*?```',
    ]

    @classmethod
    def sanitize(cls, text: str) -> str:
        """清洗用户输入"""
        for pattern in cls.INJECTION_PATTERNS:
            text = re.sub(pattern, '[REDACTED]', text, flags=re.IGNORECASE)
        return text

    @classmethod
    def build_safe_prompt(cls, template: str, user_input: str, **context) -> str:
        """构建安全的 prompt"""
        return template.format(
            user_input=cls.sanitize(user_input),
            **context
```

### 9.3 高风险操作二次确认

```python
HIGH_RISK_TOOLS = [
    'delete_account',
    'transfer_money',
    'update_permission',
    'cancel_order'
]

class ToolSecurityChecker:
    @classmethod
    def is_high_risk(cls, tool_code: str) -> bool:
        return tool_code in HIGH_RISK_TOOLS

    @classmethod
    def check_confirmation(cls, execution_id: str, tool_code: str) -> bool:
        """检查是否已确认"""
        confirm_key = f"tool_confirm:{execution_id}:{tool_code}"
        return redis.exists(confirm_key) > 0

    @classmethod
    async def request_confirmation(cls, execution_id: str, tool_code: str, params: dict):
        """请求用户确认"""
        confirmation_id = str(uuid4())
        redis.setex(
            f"tool_confirm:{execution_id}:{tool_code}",
            300,  # 5分钟有效期
            confirmation_id
        )

        # 推送确认请求到前端
        await websocket_manager.send_to_execution(execution_id, {
            "type": "confirmation_required",
            "tool_code": tool_code,
            "params": mask_sensitive_params(params),
            "confirmation_id": confirmation_id
        })

        raise WaitingForConfirmationError(execution_id, tool_code, confirmation_id)
```

```python
class PermissionChecker:
    def can_use_tool(self, user_id: str, tool_code: str, action: str = 'execute') -> bool:
        """检查是否可以使用工具"""
        # 1. 检查 RBAC 权限
        user_roles = self.get_user_roles(user_id)
        role_permissions = self.get_role_permissions(user_roles)

        has_permission = any(
            p.tool_code == tool_code and p.action == action
            for p in role_permissions
        )

        if not has_permission:
            return False

        # 2. 检查 ABAC 策略
        user_attrs = self.get_user_attributes(user_id)
        attribute_policies = self.get_attribute_policies(tool_code)

        for policy in attribute_policies:
            if not self.evaluate_condition(policy.condition, user_attrs):
                return False

        return True

    def evaluate_condition(self, expression: str, attributes: dict) -> bool:
        """使用 SpEL 评估条件"""
        try:
            parser = SpelExpressionParser()
            context = SimpleEvaluationContext()
            context.setVariable('user', attributes)
            result = parser.parseExpression(expression).getValue(context)
            return bool(result)
        except Exception:
            return False
```

### 9.5 敏感信息脱敏

```python
SENSITIVE_PATTERNS = [
    (r'password', 'password'),
    (r'secret', 'secret'),
    (r'token', 'token'),
    (r'api[_-]?key', 'api_key'),
    (r'phone', 'phone'),
    (r'mobile', 'mobile'),
    (r'id[_-]?card', 'id_card'),
]

def mask_sensitive_fields(data: dict) -> dict:
    """脱敏敏感字段"""
    masked = data.copy()

    for field, value in masked.items():
        field_lower = field.lower()
        for pattern, name in SENSITIVE_PATTERNS:
            if re.search(pattern, field_lower):
                if isinstance(value, str) and len(value) > 4:
                    # 保留前后各2位
                    masked[field] = value[:2] + '****' + value[-2:]
                else:
                    masked[field] = '[MASKED]'
                break

    return masked
```

### 10.5 成本追踪

```python
MODEL_PRICING = {
    'gpt-4.1': {'input': 0.03, 'output': 0.06},  # per 1K tokens
    'gpt-4.1-mini': {'input': 0.00015, 'output': 0.0006},
    'claude-3-opus': {'input': 0.015, 'output': 0.075},
    'claude-3-haiku': {'input': 0.00025, 'output': 0.00125}
}

BUDGET_ALERTS = {
    'workflow': {
        'flight_booking': {'daily_limit': 100, 'alert_at': 80},
        'hotel_booking': {'daily_limit': 80, 'alert_at': 60}
    },
    'user': {
        'daily_limit': 10,
        'alert_at': 8
    },
    'global': {
        'daily_limit': 1000,
        'alert_at': 800
    }
}

class CostTracker:
    def calculate_cost(self, model: str, input_tokens: int, output_tokens: int) -> float:
        """计算 LLM 调用成本"""
        pricing = MODEL_PRICING.get(model)
        if not pricing:
            return 0
        input_cost = (input_tokens / 1000) * pricing['input']
        output_cost = (output_tokens / 1000) * pricing['output']
        return input_cost + output_cost

    def track_and_alert(self, workflow_code: str, user_id: str, cost: float):
        """追踪成本并发送预警"""
        # 记录到各维度
        self.record_cost('workflow', workflow_code, cost)
        self.record_cost('user', user_id, cost)
        self.record_cost('global', 'all', cost)

        # 检查预警
        self.check_budget_alerts(workflow_code, user_id)
```
